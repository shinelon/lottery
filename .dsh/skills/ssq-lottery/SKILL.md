# 双色球分析与选号

## 何时使用

- 「跑一下双色球」「出下一期号码」「拉最新开奖记录」
- 「上期中了吗」「复盘一下」「回测结果怎么样」
- 用户提到双色球、红球蓝球、选号、走势

## 前置条件

- 项目根目录存在 `ssq.py`（纯标准库，Python 3.10+；本机命令是 `py`）
- `data/` 与 `reports/` 与 `ssq.py` 同级，脚本会自动创建
- 抓取优先走系统 `curl.exe`，`urllib` 兜底。本机 urllib 的 TLS 请求会被网络层拦截，属正常现象

## 执行流程

1. **定位根目录**：`SKILL.md` 位于 `.dsh/skills/ssq-lottery/`，脚本在 `../../../ssq.py`。
2. **运行**（在项目根目录）：

   ```powershell
   $env:PYTHONIOENCODING="utf-8"
   py ssq.py              # 联网抓 260 期 -> 分析近 100 期 -> 出下一期 5 注
   ```

   离线或抓取失败时：`py ssq.py --no-fetch`（用 `data/ssq.csv` 缓存）。
   调整窗口：`py ssq.py --window 120 --test-n 40`。

3. **读取产物**：`reports/<目标期号>.md`。向用户复述时包含：
   - 目标期号与日期、注数与成本
   - 5 注红蓝球（表格，红球已排序、补零两位）
   - 盲测结论：蓝球命中次数/百分位、红球≥3 次数/百分位、各自判定
   - 稳健性：滚动窗口跑赢个数（n/9）、参数敏感性区间
4. **只问号码时**给表；**问「准不准」时必须连结论段一起给**，不能只报命中数。
5. **复盘**：再次运行会自动把上期实际开奖回填到 `reports/history.csv`，按期号+注号去重，重复运行安全。
6. **目标期推算**：接口最新期号 +1；若当天已过 20:00 停售，顺延到下一个开奖日（周二/周四/周日）。

## 判定口径（不可简化）

- 蓝球零分布必须用**结构一致**的那种：每期 2 个蓝球按 3:2 分配，1σ≈5.3。
  不能用「200 注各自随机蓝球」（1σ≈3.4），否则会把方差误判成优势。
- **单次跳出 3σ ≠ 有效**。必须同时满足：滚动窗口多数跑赢 + 参数微调后优势仍在。
  当前项目三次证据互相矛盾，结论是「无预测能力」，不要改写成正面结论。
- 红球命中 ≥3 个的期望约 5.77%/注；命中 ≥4 个约 0.49%/注。
- 返奖率约 50%，其中 17%–25% 压在一等奖上，短样本必然碰不到头奖，
  实测回报率 15%–40% 属正常，**不能用「没回本」否定方案，也不能用「蓝球蒙对」肯定方案**。
- 单注概率：一等 1/17,721,088；二等 1/1,181,406；三等 1/109,389；
  四等 1/2,303；五等 1/129；六等 1/17；任意奖约 6.71%（1/15）。

## 常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| HTTP 403 / SSL EOF | urllib 被网络层拦截 | 确认 `curl.exe` 可用；脚本已优先用 curl |
| 数据不足 | 缓存期数 < window+10 | 联网重抓，或减小 `--window` |
| 形态过滤后无候选组合 | 和值/奇偶约束过紧 | 放宽 `form_ok` 里的和值区间 |
| 报告期号不是预期 | 已过 20:00 停售 | 正常，顺延到下一个开奖日 |

## 底线

不承诺中奖，不美化回测，不隐藏「与随机无差异」的结论。
每次输出结尾保留：本方案不改变单注概率，理性购彩。
